## 2 任务概述

### 2.1 目标

TreasureShare 的开发意图是实现一个在线玩具租赁共享平台：

1. **租客端**：用户可以浏览商品、搜索、加入购物车、下单租赁、支付、收货确认、归还、评价
2. **物主端**：用户可以发布闲置玩具、管理出租订单、发货、消毒确认
3. **管理端**：管理员可管理商品、订单、分类、用户、社区、评价，查看数据看板
4. **社交功能**：用户间即时消息聊天、社区发帖互动
5. **AI 辅助**：基于 Gemini AI 的智能推荐

预期读者：租客、物主、平台管理员。

### 2.2 用户的特点

| 用户类型 | 教育水平 | 技术专长 | 使用频度 |
|----------|----------|----------|----------|
| 租客（普通用户） | 不限 | 基础 Web 操作 | 中频（每周数次） |
| 物主（闲置玩具发布者） | 不限 | 基础 Web 操作 | 低频（每月数次） |
| 管理员 | 大专以上 | 熟悉 Web 后台操作 | 高频（每日） |

### 2.3 假定和约束

- **开发期限**：2026/3/27 — 2026/6/6（约 10 周）
- **开发人员**：1 名全栈开发者（钱嘉铭）
- **技术约束**：基于 RuoYi v3.9.2 框架，JDK 17+，MySQL 8.0+
- **部署环境**：本地 Linux 服务器
- **预算限制**：开源免费技术栈

### 3.2 对性能的规定

#### 3.2.1 精度

- **数据精度**：金额字段使用 DECIMAL(10,2)，保留两位小数
- **时间精度**：订单时间精确到秒，使用数据库 TIMESTAMP 类型

#### 3.2.2 时间特性要求

| 操作 | 响应时间要求 |
|------|-------------|
| 页面加载 | < 3 秒 |
| API 接口响应 | < 1 秒 |
| 搜索查询 | < 2 秒 |
| 图片上传 | < 5 秒（单张） |
| 登录认证 | < 1 秒 |

#### 3.2.3 灵活性

- 系统支持多级分类动态扩展，新增分类不需要修改代码
- 订单状态通过状态机模式设计，可扩展新增状态
- 前端使用组件化架构，支持快速迭代新页面
- 后端使用模块化分层架构（ruoyi-toyrental 独立模块）

### 3.3 输入输出要求

#### 典型输入项

| 输入项 | 类型 | 长度限制 | 说明 |
|--------|------|----------|------|
| 用户名 | 字符串 | 2-20 字符 | 字母、数字、下划线 |
| 密码 | 字符串 | 6-100 字符 | 加密存储（BCrypt） |
| 商品名称 | 字符串 | 1-100 字符 | 必填 |
| 商品描述 | 文本 | 1-2000 字符 | 支持富文本 |
| 租金价格 | 数字 | DECIMAL(10,2) | 元/天 |
| 押金金额 | 数字 | DECIMAL(10,2) | 元 |
| 收货地址 | 字符串 | 1-200 字符 | 省/市/区/详细地址 |
| 手机号 | 字符串 | 11 字符 | 中国大陆手机号 |
| 评价内容 | 文本 | 1-500 字符 | 可选 |
| 评价分数 | 整数 | 1-5 | 星级评分 |

#### 输出项

- 商品列表、商品详情、订单状态
- 操作成功/失败提示信息
- 错误码和错误消息（如 401 未认证、403 无权限）
- 数据看板统计图表

### 3.4 故障处理要求

| 故障类型 | 处理方式 |
|----------|----------|
| 数据库连接失败 | 返回错误提示，记录日志，Druid 自动重连 |
| Redis 不可用 | 降级处理，跳过缓存直接查询数据库 |
| JWT Token 过期 | 返回 401 状态码，前端跳转登录页 |
| 文件上传失败 | 提示用户重新上传，限制文件大小 5MB |
| 重复提交 | Redis 防重复提交拦截，返回提示信息 |
| XSS 攻击 | 系统配置 XSS 过滤器，自动清洗输入 |
| 并发冲突 | 数据库乐观锁处理 |

### 3.5 其他专门要求

- **安全性**：JWT 认证 + BCrypt 密码加密 + XSS 过滤 + Druid SQL 注入防护
- **可用性**：7×24 小时（开发阶段按需启动）
- **可维护性**：代码模块化、文档齐全
- **国际化**：当前仅支持中文（简体）

## 4 运行环境规定

### 4.1 设备

**最低配置**：
- CPU：双核 2.0GHz 以上
- 内存：8GB RAM
- 硬盘：500GB HDD
- 网络：局域网或互联网连接

**推荐配置**：
- CPU：四核 3.0GHz 以上
- 内存：16GB RAM
- 硬盘：1TB SSD
- 网络：互联网连接（100Mbps+）

### 4.2 支持软件

| 软件 | 版本 | 用途 |
|------|------|------|
| JDK | 17+ | Java 运行环境 |
| Maven | 3.6+ | 构建工具 |
| Node.js | 18+ | 前端开发环境 |
| MySQL | 8.0+ | 关系型数据库 |
| Redis | 7.4+ | 缓存和会话管理 |
| Nginx | 1.x | 反向代理（生产环境） |
| Linux | Arch Linux / Ubuntu | 服务器操作系统 |

### 4.3 接口

系统接口说明见概要设计说明书 §3 接口设计部分。

外部接口清单：

| 接口 | 协议 | 说明 |
|------|------|------|
| 前端 ↔ 后端 | HTTP/HTTPS RESTful | JSON 格式数据交互 |
| 后端 ↔ MySQL | TCP (JDBC) | 数据库连接池 (Druid) |
| 后端 ↔ Redis | TCP (Jedis) | 缓存和会话存储 |
| 后端 ↔ Gemini AI | HTTPS | AI 智能推荐 |

### 4.4 控制

- **启动控制**：通过 `start.sh` 脚本顺序启动 MySQL → Redis → 后端 → 前端 → 管理端
- **停止控制**：通过 `start.sh stop` 优雅停止所有服务
- **权限控制**：基于 JWT 的角色权限控制（`@PreAuthorize` 注解），公开端点使用 `@Anonymous` 标记
