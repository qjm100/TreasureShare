## 3 程序1（用户认证模块）设计说明

### 3.1 程序描述

完成用户的注册、登录、JWT 令牌认证。用户通过用户名和密码登录后获得 JWT Token，后续请求在 Authorization 头中携带 Token。

### 3.2 功能

- **注册**：用户通过 `/register` 注册，用户名唯一，密码 BCrypt 加密
- **登录**：通过 `/login` 验证用户名密码，返回 JWT Token（有效期 30 分钟）
- **Token 刷新**：前端在 Token 过期前自动刷新
- **权限校验**：`JwtAuthenticationTokenFilter` 拦截请求，验证 Token，设置 SecurityContext

### 3.3 性能

- 登录响应时间 < 1 秒
- JWT Token 验证在内存中完成，无数据库查询开销
- BCrypt 密码验证约 100ms

### 3.4 输入项

| 输入项 | 类型 | 长度 | 说明 |
|--------|------|------|------|
| username | 字符串 | 2-30 字符 | 用户账号，唯一 |
| password | 字符串 | 6-100 字符 | 明文密码，前端传输后后端 BCrypt 加密 |

### 3.5 输出项

- **成功登录**：`{ code: 200, msg: "操作成功", data: { token: "xxx..." } }`
- **密码错误**：`{ code: 500, msg: "用户名或密码错误" }`
- **Token 过期**：HTTP 401 Unauthorized

### 3.6 流程逻辑

**[插入 images/11-sequence-login.png]**

图3-1 用户登录时序图

认证流程：

1. 用户输入用户名密码，前端发送 POST `/login`
2. `SysLoginController.login()` 接收请求
3. `SysLoginService.login()` 通过 `SysUserMapper` 查询用户
4. `SecurityUtils.login()` 校验 BCrypt 密码
5. `TokenService.createToken()` 生成 JWT Token（包含 userId, username, deptId）
6. 返回 `{ code: 200, token: "..." }`
7. 前端存储 Token 到 `localStorage`
8. 后续所有 API 请求 headers 中携带 `Authorization: Bearer <token>`
9. `JwtAuthenticationTokenFilter` 从 headers 提取 Token，解析并验证
10. 验证通过后设置 `SecurityContextHolder`，放行请求

### 3.7 接口

- **登录接口**：`POST /login` → 参数：`{ username, password, code, uuid }`（验证码可选）
- **注册接口**：`POST /register` → 参数：`{ username, password }`
- **获取用户信息**：`GET /getInfo` → 返回用户、角色、权限

## 4 程序2（订单模块）设计说明

### 4.1 程序描述

订单模块是系统的核心业务流程，管理从下单到完成的全生命周期。实现基于状态机的订单流转模型。

**[插入 images/12-order-lifecycle.png]**

图4-1 订单生命周期状态图

### 4.2 功能

| 功能 | 接口路径 | 说明 |
|------|---------|------|
| 创建订单 | `POST /api/toy/orders` | 从购物车生成订单，状态=CREATED |
| 支付 | `PUT /api/toy/orders/{id}/pay` | 模拟支付，状态 CREATED→PAID |
| 发货 | `PUT /api/toy/orders/{id}/ship` | 物主发货，状态 PAID→SHIPPED |
| 收货确认 | `PUT /api/toy/orders/{id}/receive` | 租客确认，状态 SHIPPED→RECEIVED |
| 归还 | `PUT /api/toy/orders/{id}/return` | 租客归还，状态 RECEIVED→RETURNING |
| 确认归还 | `PUT /api/toy/orders/{id}/confirm-return` | 物主验收，状态 RETURNING→DISINFECTING |
| 消毒完成 | `PUT /api/toy/orders/{id}/disinfect` | 消毒确认，状态 DISINFECTING→COMPLETED |
| 续租 | `PUT /api/toy/orders/{id}/renew` | 续租，状态 RECEIVED→RENEWAL→PAID |
| 取消 | `PUT /api/toy/orders/{id}/cancel` | 取消订单，状态 CREATED/PAID→CANCELLED |

### 4.3 性能（以创建订单为例）

- 创建订单需检查库存、生成订单号、创建订单记录和订单明细记录，整体事务性操作 < 500ms
- 订单号生成规则：`TS` + 时间戳 + 随机数

### 4.4 输入项（以创建订单为例）

| 输入项 | 类型 | 说明 |
|--------|------|------|
| addressId | Long | 收货地址 ID |
| cartIds | Long[] | 购物车项 ID 数组 |
| remark | String(500) | 订单备注（可选） |

### 4.5 输出项（以创建订单为例）

```json
{
  "code": 200,
  "msg": "下单成功",
  "data": {
    "orderId": 1,
    "orderNo": "TS20260528123456",
    "totalRent": 150.00,
    "deposit": 500.00,
    "status": "CREATED"
  }
}
```

### 4.6 流程逻辑（以创建订单为例）

1. 前端 POST `/api/toy/orders` 携带 `{ addressId, cartIds, remark }`
2. `ToyOrderController.create()` 接收请求
3. `ToyOrderServiceImpl.createOrder()` 执行：
   a. 获取当前用户 ID（`SecurityUtils.getUserId()`）
   b. 查询购物车项（`ToyCartMapper`），校验归属
   c. 校验商品状态（在售）和库存
   d. 计算总租金和押金
   e. 生成唯一订单号 `TS` + timestamp
   f. 创建订单记录（`ToyOrder`，状态 CREATED）
   g. 创建订单明细记录（`ToyOrderItem`）
   h. 扣减库存（`ToyProductMapper.updateStock()`）
   i. 清空已下单的购物车项
   j. 返回订单详情
4. 以上操作在 Spring `@Transactional` 事务中执行

### 4.7 接口（以创建订单为例）

| 项目 | 说明 |
|------|------|
| URL | `POST /api/toy/orders` |
| 认证 | 需要 Bearer JWT Token |
| 请求体 | `{ "addressId": 1, "cartIds": [1, 2], "remark": "" }` |
| 响应体 | `{ "code": 200, "msg": "下单成功", "data": { ... } }` |
| 错误码 | 400（参数错误）, 401（未登录）, 500（库存不足/商品下架） |

## 8 程序6（管理后台）设计说明（简要）

管理后台基于 RuoYi Admin 框架（Vue 2 + Element UI），新增功能页面位于 `back/ruoyi-ui/src/views/toy/` 目录。

### 8.1 数据看板

展示平台核心数据：用户总数、商品总数、订单总数、今日新增订单数。通过 `ToyDashboardController` 提供统计数据 API。

### 8.2 订单管理

管理员可查看全部订单，支持按状态筛选、强制取消订单等操作。调用 `ToyOrderController` 的管理接口（`@PreAuthorize` 权限控制）。

### 8.3 商品管理

管理员可审核商品、强制下架商品。调用 `ToyController` 的管理接口。
