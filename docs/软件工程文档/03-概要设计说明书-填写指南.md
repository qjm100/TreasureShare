## 2 总体设计

### 2.1 需求规定

系统需要满足以下核心需求：

1. **用户体系**：注册、登录（JWT）、个人信息管理、地址管理、角色权限控制
2. **商品体系**：商品 CRUD、分类树、图片上传、搜索筛选、分页浏览
3. **订单体系**：下单→支付→发货→收货→归还→消毒→完成 的状态机流转
4. **消息体系**：用户间即时聊天、会话管理
5. **社区体系**：帖子发布、评论互动、点赞
6. **评价体系**：租后评价、星级评分
7. **管理后台**：数据看板、全模块管理
8. **AI 模块**：基于 Gemini AI 的智能推荐

### 2.3 基本设计概念和处理流程

系统采用经典的分层架构：**表现层 → 控制层 → 服务层 → 数据访问层**

**[插入 images/05-flowchart.png]**

图2-2 系统处理流程图

核心处理流程：

1. 客户端发起 HTTP 请求
2. Nginx 反向代理到前端静态资源或后端 API
3. JWT 认证过滤器校验 Token（公开端点跳过）
4. Controller 接收请求参数并校验（`@RepeatSubmit` 防重复提交）
5. Service 层执行业务逻辑
6. Mapper 层执行数据库操作
7. 结果通过 `AjaxResult` 统一封装返回 JSON

### 2.4 系统框架结构

**[插入 images/06-module-structure.png]**

图2-3 系统模块结构图

模块划分说明：

**前端层**：
- `front/` — React 19 + TypeScript + Vite 6，用户端 SPA（`src/pages/` 下 12 个页面）
- `back/ruoyi-ui/` — Vue 2 + Element UI，管理端（`views/toy/` 下新增视图）

**后端层（Maven 多模块）**：
- `ruoyi-admin` — 入口模块，`RuoYiApplication` 启动类，全部 Controller
- `ruoyi-framework` — 安全配置、JWT 过滤器、切面（DataScope、日志、限流）、全局异常处理
- `ruoyi-system` — 系统业务（用户、角色、菜单、部门、字典、通知）
- `ruoyi-toyrental` — 玩具租赁业务模块（独立模块，仅依赖 ruoyi-common）
- `ruoyi-quartz` — 定时任务管理
- `ruoyi-generator` — 代码生成器
- `ruoyi-common` — 共享层（BaseEntity、BaseController、AjaxResult、RedisCache、工具类）

**基础设施层**：
- MySQL 8.0 — 关系型数据存储
- Redis 7.4 — 缓存、会话、防重复提交
- Druid — 数据库连接池及 SQL 监控

## 3 接口设计

### 3.1 用户接口

**用户端 (React SPA)**：
- 底部导航式布局（发现、购物车、订单、消息、我的）
- 商品卡片列表 + 搜索栏
- 订单状态时间轴
- 聊天界面（类即时通讯布局）
- 社区帖子 Feed 流

**管理端 (Vue + Element UI)**：
- 侧边栏菜单 + 主内容区经典后台布局
- 数据看板（卡片 + 图表）
- 表格 + 分页 + 条件搜索（标准 CRUD 界面）
- 订单状态管理按钮组

### 3.2 外部接口

**[插入 images/15-interface-arch.png]**

图3-1 接口架构图

| 接口 | 协议 | 数据格式 | 认证方式 |
|------|------|----------|----------|
| 前端 ↔ 后端 API | HTTP/1.1 | JSON | Bearer JWT (Authorization header) |
| 后端 ↔ MySQL | TCP (JDBC) | SQL | 用户名/密码（Druid 连接池） |
| 后端 ↔ Redis | TCP (Jedis) | 键值对 | 无密码（本地） |
| 后端 ↔ Gemini AI | HTTPS/2 | JSON (REST) | API Key (环境变量) |
| 图片上传 | HTTP/1.1 | Multipart | Bearer JWT |

### 3.3 内部接口

后端模块间通过 Maven 依赖 + Spring Bean 注入实现内部接口调用：

| 调用方 → 被调用方 | 接口方式 |
|--------------------|----------|
| Controller → Service | Spring `@Autowired` 注入 Service 接口 |
| Service → Mapper | Spring `@Autowired` 注入 Mapper 接口 |
| Service → Redis | `RedisCache` 工具类方法调用 |
| 各模块 → ruoyi-common | Maven 依赖 + Bean 注入 |

## 4 运行设计

### 4.1 运行模块组合

- **模块 A**：基础系统（ruoyi-admin + ruoyi-framework + ruoyi-system + ruoyi-common），提供认证、用户管理、权限控制
- **模块 B**：玩具租赁业务（ruoyi-toyrental），提供商品、订单、购物车、消息、社区、评价等核心业务
- **模块 C**：前端（React 用户端 + Vue 管理端）

### 4.2 运行控制

启动顺序：
1. 启动 MySQL 服务 → `sudo systemctl start mysqld`
2. 启动 Redis 服务 → `redis-server`
3. 启动后端 → `java -jar ruoyi-admin.jar`
4. 启动前端 → `npm run dev` (React / Vue)
5. 或一键启动 → `./start.sh start`

### 4.3 运行时间

| 操作 | 预计时间 |
|------|----------|
| 后端服务启动 | 约 10 秒 |
| 前端热更新编译 | 约 2-5 秒（开发模式） |
| 数据库初始化 | 约 30 秒（首次导入 SQL） |
| API 请求处理 | < 1 秒 |
| 图片上传处理 | < 5 秒 |

## 6 系统出错处理设计

### 6.1 出错信息

| 异常或出错分类 | HTTP 状态码 | 界面提示信息 |
|---------------|------------|-------------|
| 未登录/Token 过期 | 401 | "请先登录" |
| 无操作权限 | 403 | "没有访问权限" |
| 资源不存在 | 404 | "请求的资源不存在" |
| 参数校验失败 | 400 | 具体字段错误提示（如"商品名称不能为空"） |
| 重复提交 | 200 (code:500) | "请勿重复提交" |
| 服务器内部错误 | 500 | "系统错误，请联系管理员" |
| 文件过大 | 413 | "文件大小超过限制（最大5MB）" |
| 用户名或密码错误 | 200 (code:500) | "用户名或密码错误" |

### 6.2 补救措施

1. **后备技术**：MySQL 定期备份（`mysqldump`），Redis 数据为非关键缓存可丢失重建
2. **降效技术**：Redis 不可用时，直接查询数据库（牺牲部分性能但不影响功能）
3. **恢复及再启动**：`start.sh restart` 一键重启所有服务，Spring Boot 应用崩溃后通过进程管理自动重启
