## 1 引言

### 1.1 编写目的

TreasureShare 系统采用 MySQL 8.0 作为数据存储引擎，使用 MyBatis ORM 框架进行数据访问。本报告描述系统的数据库标识符、约定、概念结构设计（E-R 图）、物理结构设计（数据字典）及安全保密设计。

### 1.2 背景

- **名称**：ry-vue（TreasureShare 数据库）
- **数据库系统**：MySQL 8.0

### 2.2 使用它的程序（连接数据库）

TreasureShare 后端使用 Druid 连接池连接 MySQL 数据库，配置位于 `application-druid.yml`：

- **JDBC URL**：`jdbc:mysql://localhost:3306/ry-vue?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8`
- **驱动类**：`com.mysql.cj.jdbc.Driver`
- **连接池**：Druid（初始 5，最大 20）
- **数据访问**：MyBatis Mapper XML 配置 SQL

### 2.3 约定

- 主键统一使用 `bigint(20) NOT NULL AUTO_INCREMENT`
- 表名采用蛇形命名法（snake_case），如 `toy_product_image`
- 字段名采用蛇形命名法，如 `rent_price_day`
- Java 属性采用驼峰命名法，由 MyBatis 自动映射
- 所有表使用 InnoDB 引擎，字符集 utf8mb4
- 时间字段使用 `datetime` 类型
- 金额字段使用 `decimal(10,2)` 类型
- 逻辑删除使用 `del_flag` 字段（0=正常, 2=删除）
- 状态字段使用 `char(1)` 类型，如 `status`（0=正常, 1=停用）
- 每个表包含标准字段：`create_by`, `create_time`, `update_by`, `update_time`, `remark`

### 2.4 专门指导

可查看 `back/sql/ry_20260417.sql` 了解完整建表语句。使用 Druid 监控页面 `http://localhost:8080/druid/` 查看 SQL 执行统计。

### 2.5 支持软件

- MySQL 8.0
- Druid 1.2.x
- MyBatis 3.x

核心实体关系描述：

1. **用户 (sys_user) — 商品 (toy_product)**：一对多。一个用户（物主）可发布多个商品。
2. **用户 (sys_user) — 订单 (toy_order)**：一对多。一个用户可作为租客或物主关联多个订单。
3. **商品 (toy_product) — 订单明细 (toy_order_item)**：一对多。一个商品可被多次租赁。
4. **订单 (toy_order) — 订单明细 (toy_order_item)**：一对多。一个订单可包含多个商品。
5. **用户 (sys_user) — 购物车 (toy_cart)**：一对多。一个用户的购物车可有多个商品项。
6. **商品 (toy_product) — 评价 (toy_evaluation)**：一对多。一个商品可有多条评价。
7. **订单 (toy_order) — 评价 (toy_evaluation)**：一对一。一条订单完成后方可评价。
8. **分类 (toy_category) — 商品 (toy_product)**：一对多。一个分类下可有多个商品，分类支持树形结构（parent_id）。
9. **用户 (sys_user) — 地址 (toy_address)**：一对多。一个用户可有多个收货地址。

### 4.2 安全保密设计

1. **用户密码**：使用 BCrypt 加密存储，不可逆
2. **SQL 注入防护**：
   - MyBatis 使用 `#{}` 参数化查询
   - XSS 过滤器清洗输入
   - Druid SQL 防火墙
3. **权限控制**：
   - 用户认证：JWT Token 每 30 分钟过期
   - 角色权限：`@PreAuthorize` 注解 + `ss.hasPermi()` 方法级控制
   - 数据权限：`@DataScope` 注解实现行级数据隔离
4. **访问控制**：Druid 监控页面需用户名密码访问（`ruoyi` / `123456`）
5. **逻辑删除**：使用 `del_flag` 字段，数据不物理删除
