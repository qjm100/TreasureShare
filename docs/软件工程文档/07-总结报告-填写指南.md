### 2.3 基本流程

**[插入 images/05-flowchart.png]**

图2-1 系统处理流程图

系统的核心处理流程为：

1. 用户通过浏览器访问用户端（React SPA）或管理端（Vue Admin）
2. HTTP 请求经 JWT 认证过滤器校验身份（公开端点跳过）
3. Controller 层接收请求参数，Service 层执行业务逻辑
4. Mapper 层通过 MyBatis 操作 MySQL 数据库
5. 结果统一封装为 `AjaxResult` 格式返回 JSON 给前端
6. Redis 提供缓存加速和防重复提交支持

订单核心业务流程：

```
下单(CREATED) → 支付(PAID) → 发货(SHIPPED) → 收货(RECEIVED)
                                                   ↓
           完成(COMPLETED) ← 消毒(DISINFECTING) ← 归还(RETURNING)
```

## 3 开发工作评价

### 3.1 对生产效率的评价

技术方案选型合理：
- 后端采用 RuoYi（若依）框架，提供了成熟的认证、权限、代码生成等基础设施，大幅减少重复开发工作
- 前端采用 React 19 + Vite 6，热更新极快，开发体验优秀
- MyBatis 灵活映射，Druid 实时 SQL 监控便于调优
- 模块化分层架构使前后端可并行开发

### 3.2 对产品质量的评价

**功能完整性**：对照《需求分析报告》的功能规定，全部计划功能均已实现。核心业务流程（订单状态机流转）逻辑正确，各模块之间接口清晰。

**测试结果**：Playwright E2E 测试覆盖核心业务场景，测试结果见《测试报告》。

**质量亮点**：
- JWT 无状态认证 + BCrypt 密码加密确保安全性
- 订单状态机模式保证状态流转正确性
- Druid 连接池自动重连，Redis 降级处理保证可用性
- 移动端浏览器响应式适配通过 iPhone 14 Pro 视口测试

**不足之处**：
- 支付为模拟支付，未对接真实支付网关
- 消息采用轮询方式，非 WebSocket 实时推送
- 搜索仅支持 LIKE 模糊匹配，不支持全文检索

### 3.3 对技术方法的评价

本项目采用的技术方法：

- **后端**：Spring Boot + MyBatis + Druid + JWT + Redis
- **用户端前端**：React 19 + TypeScript + Vite 6 + Tailwind CSS 4
- **管理端前端**：Vue 2 + Element UI
- **数据库**：MySQL 8.0（InnoDB 引擎，utf8mb4 字符集）
- **测试**：Playwright E2E 测试

综合评价：

| 技术项 | 评价 | 说明 |
|--------|------|------|
| Spring Boot + RuoYi | 优 | 成熟稳定，基础设施完善，开发效率高 |
| MyBatis | 良 | SQL 灵活可控，但 XML 维护成本较高 |
| JWT 认证 | 优 | 无状态认证，适合前后端分离架构 |
| React + TypeScript | 优 | 类型安全，组件化开发效率高 |
| Tailwind CSS | 优 | 原子化样式，开发效率高 |
| MySQL 8.0 | 优 | 稳定可靠，满足项目需求 |
| Druid | 优 | SQL 监控功能实用 |

## 4 经验与教训

通过本次 TreasureShare 项目开发，我们总结出以下经验与教训：

1. **制定详细计划并严格执行**：项目初期制定的甘特图和里程碑计划有效指导了整个开发过程，各阶段按时完成。

2. **框架选型决定开发效率**：RuoYi 框架的代码生成器和基础设施模块节省了大量重复开发时间，但框架体积较大，部分旧版本依赖需要适配升级。

3. **文档与代码同步推进**：本次在编码完成后集中编写文档，发现部分设计细节需要回看代码确认。建议后续项目中文档先行，详细设计文档在编码前完成。

4. **测试应尽早介入**：Playwright E2E 测试在开发后期才引入，未能发挥测试驱动开发的优势。后续应先在关键路径上编写测试用例，再实现功能。

5. **模块化架构便于团队协作**：后端 `ruoyi-toyrental` 独立模块设计 + 前端组件化架构，使各成员可按分工独立开发。

6. **前后端分离开发**：React 用户端通过 Vite 代理 + JWT 认证，与后端完全解耦，前后端可并行推进。
